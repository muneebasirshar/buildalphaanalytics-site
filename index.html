Build 01Worked example

Three Copilot agents, built end to end

One method, three levels of ambition: a helper that answers from a single document, a policy agent for the whole organisation, and an assistant that drafts replies and flags what must be escalated.

01

Returns & Warranty Helper

Decides covered or not, from one source, in a three-line verdict.

02

HR Policy Agent

Answers from several policy sources, cites the section, and redirects what it should not answer.

03

CS Email Assistant

Drafts the reply in the house template, flags escalations and leaves unknowns in brackets.

Agents draft. People decide.

AgentDrafts the reply
PersonReviews and fills the brackets
PersonDecides and sends

Version one drafts. It does not send. Escalation limits live in one shared place, so a threshold changes once and every agent updates.

Build 03Microsoft Fabric

Apps on Microsoft Fabric

From governed data in OneLake to apps people actually use: reports that write back, agents that answer in plain English, and functions any system can call.

How a Fabric app fits together

Data agents

Ask questions of your data in plain English. Each agent is set up with your own instructions and example queries, is read-only, and only shows people what their permissions allow.

Write-back from Power BI

Turn a report into a working app. Reusable functions let people add, update or delete records from the report itself, instead of switching to a spreadsheet.

One governed foundation

Reports, agents and apps all read the same OneLake data and the same semantic model, so every number agrees and access rules are set once.
